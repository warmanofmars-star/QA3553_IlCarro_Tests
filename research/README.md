# research/ — исследование фактического поведения IlCarro

У IlCarro нет SRS и STD, поэтому ожидаемые результаты тестов восстанавливаются по источникам
(иерархия — в `docs/requirements/README.md`). Скрипты в этой папке собирают **факты**
о фактическом поведении приложения: какой запрос отправили, что получили (статус, тело ответа,
текст на экране, URL, содержимое localStorage). Оценок («баг», «правильно») в логах нет:
выводы делаются отдельно, на основе источников более высокого уровня.

Результат работы скриптов — `docs/requirements/research-log.md`.

## Файлы

| Файл | Что делает |
|------|-----------|
| `explore_api.py` | Вопросы Q-API-01 … Q-API-18: запросы к бэкенду через `requests` |
| `explore_ui.py` | Вопросы Q-UI-01 … Q-UI-14: Playwright (sync API, headless) |
| `explore_ui_interception.py` | Вопросы Q-UI-15 … Q-UI-19: Playwright с перехватом запросов (`page.route`); машин не создаёт |
| `explore_ui_rest.py` | Вопросы Q-UI-20 … Q-UI-26 (шаг 6.3b): Playwright; пишущие запросы перехвачены, машин не создаёт |
| `probe_session_tokens.py` | Вопросы Q-API-19 … Q-API-21 (шаг 6.4a): два входа одним пользователем, срок жизни токена (claims JWT), операции API по Swagger; один пользователь, машин не создаёт |
| `explore_ui_faults.py` | Вопросы Q-UI-27 … Q-UI-40 (шаг 7a): Playwright, сбои бэкенда в UI — статусы ошибок, обрыв, задержка на запросах, которые экраны реально отправляют (`--run 7a`, лог `explore_ui_faults_run<N>.log`, `--only` — отдельные ячейки). Пишущие запросы перехвачены (кроме намеренного 401 в `car.real401`), машин не создаёт. Пользователь — из `evidence/explore_ui_faults_user.txt`; если файла нет, регистрирует одного через API и записывает его email туда |
| `race_journal_append.py` | Не о приложении, а о фреймворке: портятся ли журналы прогона (`logs/*.jsonl`), когда несколько процессов дописывают их одновременно; сеть не нужна |
| `common.py` | Общие функции: запросы, временные пользователи, маскирование токенов, чистка |
| `evidence/` | Логи прогонов и скриншоты. В git не хранятся (`.gitignore`), создаются скриптами |

Имена скриптов не начинаются с `test_`, поэтому `pytest` их не собирает.
Каждый вопрос — отдельная функция с ID в имени, например `q_api_01_booking_state`.

## Как запускать

Из корня репозитория, с активированным виртуальным окружением проекта:

```bash
python research/explore_api.py --run 1
python research/explore_ui.py  --run 1
```

- `--only Q-API-13,Q-API-14` — выполнить только перечисленные вопросы (пробы нового шага без повтора старых).
- `--run N` — номер прогона; лог пишется в `research/evidence/explore_<api|ui>_run<N>.log`.
  Чтобы сравнить два прогона: `diff research/evidence/explore_api_run1.log research/evidence/explore_api_run2.log`.
- Базовые адреса берутся из `API_BASE_URL` и `UI_BASE_URL` (по умолчанию как в тестах проекта).
- `.env` скрипты не читают. Используются только временные пользователи `probe_<uuid>@example.com`,
  которые создаются через API.
- Токены в логах заменяются на `<hidden>`; email и серийные номера — на метки `<user1>`, `<car1>`,
  поэтому логи двух прогонов сопоставимы.
- Все созданные машины удаляются в блоке `finally`. В конце скрипт печатает, сколько пользователей
  и машин создано и сколько машин удалено. Пользователей API удалять не умеет, они остаются.
- Бэкенд общий и внешний: прогон занимает несколько минут, число машин в больших городах
  (например, Tel Aviv) может меняться между прогонами по независящим от скрипта причинам.
